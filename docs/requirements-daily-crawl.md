# 要件定義: 日次クロール(値下げ追跡+新着探索)

status: 確定(2026-08-12 未決事項Q1〜Q4をユーザー決定・実装済み) / 実装: `crawler/daily.mjs` + `.claude/skills/daily-crawl` + Claude Code Routine

## 1. 目的

1. **値下げの時系列追跡**: 台帳物件の売出価格を毎日観測し、price_history に「いつ・いくら下げたか」を
   自動蓄積する。掲載期間×値下げ幅の実測データを台帳内で完結させる(レインズ照会に頼る範囲を縮小)
2. **新着の取りこぼし防止**: 対象エリア・価格帯の新規売出を毎日検出し、翌朝までに知る
3. **掲載終了(成約疑い)の検出**: 消えた物件を記録し、成約価格照合(データ台帳の検証)の手がかりにする

## 2. スコープ

### 2.1 watch: 既存台帳の更新チェック
- 対象: `properties/*.yaml` のうち `source_url` を持つ全物件(2026-08-12時点 17/17件。以後の登録分も自動対象)
- 取得: 掲載ページから 価格 / 情報提供日 / 掲載状態 を抽出
- 検出と処置:
  - **値下げ/値上げ**: price_history 最終値と差 → `price_history` へ追記(date=媒体の情報提供日、
    コメントにクロール日)→ エンジン再査定 → 判定反転の有無をレポート
  - **掲載終了**: 物件YAMLに `delisted_observed: {date, http_status}` を記録。**成約とは断定しない**
    (取り下げ・媒体替えの可能性。確定はレインズまたは成約データ出現時)。status変更はユーザー判断
  - **変化なし**: 何も書かない(コミットも発生させない)

### 2.2 discover: 新着探索
- 検索元: SUUMO+athome の北区一覧(各 中古一戸建て+新築一戸建て。athomeは2026-08-12のPhase 2で追加。
  契機: 中十条4・7,990万のSUUMO非掲載物件がathome系集約(ニフティ)にのみ存在した実例)。
  媒体横断の同一物件は指紋(地区丁目|価格|土地面積|建物面積)で名寄せしSUUMO優先。
  **設計方針(2026-08-12改訂)**: 取りこぼし(別戸を重複と誤断)より重複報告のほうが安全なため、
  指紋は厳しめ(4項目)にし、台帳と一部だけ一致する新着には `sibling_hint` で確度を出し分ける
  ([別戸の可能性・要判断]/[別戸または価格改定・要判断]/[同一戸の疑い])。
  **価格一致を同一物件の根拠にしない**——新築の複数戸掲載は一覧が開発の代表価格(最安戸)を
  出すため、別戸が同価格で表示される(西が丘2の1号棟/2号棟で実際に取りこぼした)
- 条件: 価格 **5,000〜9,000万円** / **赤羽圏12地区限定**(上十条・中十条・十条仲原・岩淵町・志茂・
  神谷・西が丘・赤羽・赤羽北・赤羽南・赤羽台・赤羽西。他地区は破棄) / **徒歩20分以内**
- 既知除外: SUUMO物件番号(nc_)を (a) 台帳の source_url、(b) `market/crawl/seen.json` と突き合わせ。
  一度レポートした物件は再レポートしない(価格が変わった場合のみ再掲)
- 処置(2026-08-13改訂・ユーザー指示): **ノックアウトファクター非該当の新着は自動登録まで実施する**。
  KO判定は**スクリプト側で機械的に行う**(`crawler/screen.mjs`)。Claudeは判定結果と
  詳細ページの抽出値を受け取り、KO非該当のものだけ fudosan-appraisal スキルの登録フロー
  (YAML作成→エンジン査定→検証→デプロイ)を無人で完遂し、結果を事後報告する。
  - **2段階スクリーニング(段階1で確定するものは詳細を取りに行かない=無駄取得ゼロ)**:
    - 段階1(取得ゼロ): `excluded.json` の除外済み**現場**と諸元照合(地区+丁目+土地/建物面積)。
      完全一致=同一戸の別業者掲載として即ブロック。近接(±1.5m²)=`suspect` として人へ回す
    - 段階2(1物件1取得): 生き残りのみ詳細ページを取得し、対象物件の欄だけをスキャンして
      KO信号を抽出+査定入力の実値(土地/建物/間取り/築年月/徒歩/接道/用途地域/建ぺい容積/
      権利/情報提供日)を返す
  - レポートの `event` は `new`(登録対象) / `new_ko_blocked` / `new_ko_suspect` / `new_out_of_scope`。
    落とした件数も summary に開示する(黙って減らさない)
  - **徒歩分は詳細ページの値を正とする**。一覧カードの徒歩分は隣接カードを巻き込んで
    過小に出る(2026-08-13実測: 一覧4分/1分に対し詳細16分)。詳細で上限20分超なら圏外として落とす
  - **ノックアウトファクター(1つでも該当なら登録せず報告のみ)**:
    KO1 再建築不可・接道義務不適合の明記 / KO2 土地権利が所有権以外(借地権・定期借地) /
    KO3 告知事項(心理的瑕疵)の明記 / KO4 土砂災害特別警戒区域等の重大ハザード
    (**掲載への明記だけでなく、excluded.json の除外済み現場との諸元照合を必須とする**。
    同一現場の別業者掲載は媒体番号が変わって現れ、制限事項を書かない掲載がある。
    実例: at_1106854114=レッドゾーン2号棟の別業者掲載・土砂災害の記載なし) /
    KO5 必須項目(価格・所在地・土地面積・建物面積)が詳細ページから確定できない(誤登録防止)
  - **スキャンは対象物件の欄に限定する**(その他制限事項・法令等制限・告知事項・権利・現況・
    接道・athomeBiko)。ページ全体を舐めると埋め込みJSONの**他物件**の広告文
    (「■再建築不可」等)を拾い、全件が毎日ブロックされる(2026-08-13の実ページで再現・回帰テスト済)。
    裏返しの限界として、列挙外の欄に書かれたハザードは素通りする。これは段階1の現場照合と
    登録時の両媒体確認で補う
  - 価格帯5,000〜9,000万・12地区・徒歩20分の事前フィルタは従来どおりクローラ側で適用済み
  - データ規律は従来どおり維持: assumed明示・source_urlの実在確認・推測での行追加禁止。
    事前承認は不要(2026-08-12ルール0の確立済みワークフローに組込み)だが、登録した事実と
    判定サマリは必ず報告・通知に載せる

## 3. 実行アーキテクチャ

役割分担は既存スキルの原則を踏襲: **スクリプトが観測、Claudeが台帳反映と検証**。

1. `crawler/daily.mjs`(Node ESM・依存なし): 取得・抽出・差分計算のみ。
   出力は機械可読な差分レポート(JSON)。**YAMLの書き換えはしない**
2. Routine(Claude Code): fresh session で毎日起動し、
   `node crawler/daily.mjs` → 差分あり時のみ YAML反映 → `npm test` → `node site/build.js` →
   SVG機械検査 → main へ ff-merge → デプロイ確認(curl) → 完了通知
3. 通知: Routine の完了通知(push)。本文は「値下げn件/新着n件/掲載終了n件/エラーn件」+明細

## 4. 機能要件(詳細)

- F1 価格抽出は物件詳細ページの本体価格のみ(諸費用・月々支払い表記を誤検出しない)。
  抽出失敗は「不明」としてエラー計上(0円や前回値の複写をしない)
- F2 price_history 追記は 同日・同値の重複を禁止(冪等: 同日に2回走っても差分ゼロ)
- F3 日付の優先順: 媒体の情報提供日 > クロール日。情報提供日が取れない場合はクロール日を使い
  `assumed` コメントを付す
- F4 判定反転(保留⇄見送 等)が起きた場合、レポート先頭で明示する
- F5 seen.json には nc番号・初見日・初見価格・住所のみ記録(写真・紹介文・キャッチコピーは保存禁止=公開repo規律)
- F6 掲載終了の翌日以降も7日間は再確認し、復活(再掲載)したら delisted_observed を解除して記録

## 5. 非機能要件

- N1 **マナー**: リクエスト間隔2秒以上・1実行あたり最大60ページ(watch 17 + discover 32 の最大需要49を吸収。
  2026-08-12監査で45では不足かつ超過時に例外でプロセス全体が落ちる実装だったため、上限到達は
  「discoverを打ち切り errors[] に開示」へ変更)。
  通常ブラウザ相当のUA。robots/利用規約の範囲の個人利用閲覧に留める
- N2 **失敗の可視化**: ページ構造変化・ネットワーク断は握りつぶさずエラーとして通知。
  同一物件が3日連続抽出失敗ならセレクタ改修タスクとして警告
- N3 **無人日ゼロ作業**: 変化なしの日はコミット・デプロイ・ユーザー作業が一切発生しない
- N4 実行時刻: **毎朝 07:00 JST**(=22:00 UTC 前日。Routine `fudosan-daily-crawl` の cron `0 22 * * *`。
  サーバ側が作成分にアンカーするため実際の起動は 07:0x JST)
- N5 実行環境の前提検証: Routine のfreshセッションから suumo.jp への egress が通ること
  (本セッションでは確認済み。初回Routine実行時に再確認)

## 6. データ設計

- `properties/*.yaml`: price_history 追記(既存形式)/ delisted_observed(新規・任意項目)
- `market/crawl/seen.json`(新規): `{ "nc_XXXX": {first_seen, price_man, address}, ... }`
- クロール生ログはリポジトリに入れない(セッションのscratchのみ)

## 7. 受入基準

- A1 値下げ発生(情報提供日更新)から24時間以内に price_history・本番サイトへ反映
- A2 条件合致の新着が24時間以内に通知に載る
- A3 テスト失敗状態での push がゼロ(exit code を直接検査するフローをスクリプト化)
- A4 変化なし日の通知は1行サマリのみ(またはpush抑制)。誤追記(重複・別物件混同)ゼロ
- A5 3週間運用して手動介入が「新着の登録判断」以外に発生しないこと
