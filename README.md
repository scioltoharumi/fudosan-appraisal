# fudosan-appraisal

赤羽エリアの中古戸建購入検討のための査定パイプライン。物件テキストを構造化YAMLにし、検証済み査定エンジン(simulator v1.2移植)で「売出価格 − 土地値 − 解体費 − 建物残価 − 繰延修繕」を分解し、静的サイトとして公開する。買う/見送るの判定はエンジンでは行わない(2026-08-13。人が決める判断であるため、参照水準に対する位置を事実として出すところまで)。

- 一覧: 売出価格・市場実勢中央値・乖離額・適正中央値 + 人が設定する検討状況(新規/検討中/保留(値下げ待ち)/見送り)と内見(未/内見希望/内見済)とメモ(ブラウザ保存)
- 詳細: 価格スケール / 明細 / モンテカルロ分布(seed固定) / 感度分析 / **算出根拠の全文開示** / モデル外チェックリスト / 採用した仮定一覧

## 戸建"賃貸"台帳(2026-08-18に併設)

同じ北区で**借りる**側の台帳。購入とは**データもエンジンも別系統**で、同じ静的サイトに同居する
(`rentals/` + `engine/rent.js` + `market/rent-listings.csv` + `crawler/rent-*.mjs` + `site/templates/rent-*.js`)。

- **主役は相場判定ではなく「実質月額」**。賃貸の成約賃料は公開されておらず、購入の「適正価格」に
  相当する問いが立たないため、礼金・仲介手数料・保証料・火災保険・鍵交換・付帯費用を居住月数で均し、
  更新料と退去時費用を足した額を出す。表示21万の物件が2年居住で25.1万/月になる、という事実が中心。
- **母集団は成約ではなく募集賃料**で、SUUMO単独(athomeにのみ出る一戸建てが8〜10件あり被覆は約85%)。
  この非対称は標本を増やしても解消しないため、ページで明示する。
- **ペット(猫)は「不可の明記」だけを落とす**。入居条件欄も設備欄も任意記載で、母集団54物件のうち
  記載なしが34物件あるため、「書いていない=不可」と読み替えると候補がほぼ消える。
  一覧の絞り込みで人が切り替える。「ペット相談」＝猫可とは限らない(小型犬のみの掲載がある)。
- 掲載は**物件単位に名寄せ**してある(同一物件が複数店舗から掲載されるため、掲載のまま数えると
  同じ物件を何度も数えることになり残差が実際より狭く出る)。

## 使い方

```bash
node engine/cli.js <property-id>   # 査定サマリ(--json で全結果)
npm test                           # 不変条件スイープ + 回帰値
npm run build                      # site/dist/ に静的サイト生成
```

依存はゼロ(js-yamlはvendor/に同梱・MIT)。npm install不要、オフラインでビルド可。

## 構成

```
engine/     査定コア(pure function)・CLI・YAML入出力 / rent.js(賃貸の実質月額と募集賃料モデル)
properties/ 購入の物件YAML(1物件1ファイル)
rentals/    賃貸の物件YAML(1物件1ファイル)
market/     エリア別基準坪単価(公示×1.15フォールバック) / rent-listings.csv(募集賃料プール)
crawler/    SUUMO・athomeの日次クロール / 公式ハザード照合 / http.mjs(UA・間隔・取得予算の共通部品)
site/       静的サイトビルダー・テンプレート
tests/      floor<=fair全域スイープ・lo<=mid<=hi・NaN不発生・回帰値・開示文のガード
.github/    push契機で test→build→GitHub Pages
.claude/    Claude Code スキル(パース→確認→査定→反映 / 賃貸台帳の運用)
```

## 記載ルール(publicリポジトリのため厳守)

- 書いてよいもの: 物件の**事実データ**(価格・面積・所在地・設備)と査定パラメータのみ
- 書かないもの: 指値方針・交渉メモ・個人的所感
- 物件写真・紹介文・キャッチコピーの格納禁止(著作権・媒体規約)

## 免責

本リポジトリの査定は公開データに基づく個人検討用の簡易モデルであり、不動産鑑定評価・投資助言ではない。係数は市場慣行の近似値で統計的推定ではない。サイトにはnoindexを付与している。
